# OfferFlow · 微信小程序

独立的微信原生小程序，腾讯云 CloudBase 保存数据和私有文件，无 AI 功能。无需启动原网站、PostgreSQL、MinIO 或本地 Node 服务。

## 开始使用

使用微信开发者工具导入**本目录**，按 [腾讯云部署指南](./docs/腾讯云部署指南.md) 完成 AppID、云环境、权限和云函数配置。默认 AppID 是导入占位值，云环境为空；未配置时显示连接状态，不会生成演示资料或退回本地存储。

**交付状态：源码已实现，云环境待用户创建和部署，待用户人工验收。** 本次没有运行测试、类型检查、Lint、构建或浏览器验收。

## 使用结构

- **今日**：下一项安排、求职概览、一周日历、逾期事项、面试复盘。
- **求职**：搜索、进行中 / 待投递 / Offer / 已结束筛选、收藏、岗位编辑、投递简历、JD 文本和图片、阶段推进、进展记录。
- **资料**：问题与回答、按行批量导入并跳过完全相同的问题、经历、PDF 简历、简历与经历关联。
- **快捷添加**：岗位、面试、测评 / 笔试、待办、问题、经历、简历。

所有业务详情和编辑使用同一底部面板，入口之间不压入页面栈。面板切换替换当前内容，关闭即回到原列表。每个表单只有一次保存；有未保存内容时关闭会确认。

面试和测评可选固定时段或截止时间。固定时段日程做全局时间冲突拦截；截止时间完成面试/测评后记录为完成时刻前一小时的实际时段。面试完成进入复盘，并可从面试详情直接记录带来源的问题。获得 Offer 或结束岗位会取消尚未完成的日程，已有记录保留。

## 独立性

```text
wechat-miniapp/
├── project.config.json       微信开发者工具入口
├── miniprogram/              原生 WXML / WXSS / JavaScript
│   ├── config.js             云环境 ID
│   ├── pages/home/           三个主入口、统一底部面板
│   ├── services/             云函数调用
│   └── utils/                展示模型和时间处理
├── cloudfunctions/offerflow/ 云端身份、业务规则、数据访问
├── cloudbase/                数据库及存储权限规则
└── docs/                     部署、架构和人工验收
```

没有引用原网站的模块或依赖；原网站代码、启动脚本、认证、数据库结构和 AI 配置未修改。本目录可以复制到其他位置单独开发。外层仓库仍用于 Git 交付；唯一的共享文档变更为项目迭代记录。

## 数据与边界

微信身份通过云函数上下文取得，客户端不能指定用户身份。数据库禁用客户端直接读写，文件仅创建者可读写。简历支持 PDF；JD 支持 JPG/PNG；面试材料支持 PDF/UTF-8 TXT。单文件最多 5 MB，TXT 最多 1 MB，云端校验文件签名。

首版采用每个微信账户一个工作区文档，使用版本条件更新避免并发覆盖。结构化数据上限为 700 KiB，超过时明确拒绝写入，既有资料不截断；附件字节放在独立云存储，不占该上限。长期大量存档的用户可先导出并清理旧记录；面向大规模长年使用前应将实体拆成独立集合，参见 [架构说明](./docs/架构说明.md)。

不自动迁移或同步原网站的数据，不共用原网站邮箱账号。小程序里的“导出全部资料”生成结构化 JSON 和私有文件 ID 清单，**不打包文件原文，也不提供自动恢复导入**。需要文件副本时在 PDF 预览菜单中保存。

日程时间按手机本地时区输入与显示，云端保存 UTC；无订阅消息推送。FAQ 导入只做文本规则和完全相同问题去重，不做语义合并。原网站的 AI、邮箱登录及多层详情路径均未移植。
