# 架构与交互

## 设计依据

用户在 2026-10-09 明确要求：另建微信小程序，不影响现有网站；数据库放腾讯云；删除 AI；按手机操作重新设计，便捷简单，避免多层跳转；视觉干净、主次清晰，页面不放解释性说明。

现有网站的 `README.md`、`src/db/schema.ts` 和 `src/modules/job-workflow/interface.ts` 提供岗位、时间安排、简历、经历、FAQ、复盘和事件关系的依据。本版本独立实现这些业务，不导入原网站模块。

## 产品结构

使用一个原生页面承载三个平级入口；主入口切换保留云端数据，重置局部搜索。统一面板展示详情、创建和编辑，不使用 `navigateTo` 堆叠页面。面板里进入关联资料时替换当前面板，关闭即回到主入口。

采用暖白背景、森林绿主操作、低饱和辅助色、留白和细分隔线。今日的下一项安排是唯一大面积深色卡片；列表用公司、岗位、阶段、下一项安排构成层级。图标直接用 WXSS 绘制，无远程图片或字体依赖。界面保留操作名称、输入标签、状态和必要的错误/删除/隐私确认，部署技术说明只放文档。

## 与网站的映射

| 原网站能力 | 小程序处理 |
| --- | --- |
| 工作台、日历、待办 | 合并到今日，七天切换、日期选择、逾期列表和直接完成 |
| 岗位与 JD | 求职卡片与同页详情，文字 JD、私有 JPG/PNG 附件 |
| 投递、测评、面试、Offer、结束 | 统一阶段及安排面板；测评/面试创建联动岗位阶段 |
| 截止时间面试、测评 | 完成时转为完成前一小时的固定时段 |
| 面试复盘、Transcript | 文字复盘、PDF/UTF-8 TXT 私有材料 |
| 简历、经历、FAQ | 资料入口；简历关联多条经历，问题关联经历和来源面试 |
| FAQ 批量导入 | 按行解析，最多 100 条，只跳过完全相同的问题 |
| Timeline、通用进展 | 业务动作自动留事件，另有手动记录进展 |
| 邮箱账号 | 微信云函数身份，账号与数据独立 |
| AI 相似度匹配及审核队列 | 不实现；没有 AI 代码、模型配置或调用链 |
| 深层详情路由 | 同层面板替换 |
| 原网站历史资料 | 不迁移、不同步；仍留在原数据库 |

简历聚焦 PDF，面试材料聚焦 PDF/TXT；未移植二进制录音或 Word 编辑，也无录音、语音识别、内容生成。测评和笔试作为同一种日程，标题可直接区分。

## 后端边界

```text
微信原生页面
  ├── wx.cloud.callFunction → offerflow → offerflow_workspaces
  └── wx.cloud.uploadFile / downloadFile → 私有云存储
```

云函数从 `getWXContext()` 取得微信身份，并验证配置的 AppID。工作区 `_id` 是 AppID 与 OpenID 的 SHA-256，调用者不能指定工作区 ID。每次数据库访问都由云函数计算当前 owner；数据库规则拒绝客户端直接访问。

每个工作区保存 jobs、agenda、notes、resumes、assets、events、上传预约、待删队列和最近 64 个幂等请求标识。所有业务写入先验证字段与关联关系，再用 `_id + owner + revision` 条件更新整个工作区；数据库单文档更新原子执行。不依赖应用进程内锁，也不在读写之间覆盖其他设备的新版本。

重复请求返回现有结果；请求 ID 同时派生确定的业务记录 ID。旧版本提交明确返回 `STALE`，前端刷新数据并保留表单，需用户查看后再次保存。网络失败不会展示保存成功。64 条幂等窗口外的旧请求仍受到 revision 限制，不会直接覆盖新数据。

删除岗位联动删除日程、事件、岗位及面试附件，保留问题与经历并解除已删除来源。删除经历解除问题和简历关联；被岗位使用的简历不能直接删除。结束岗位或记录 Offer 会取消待完成日程，重新开启阶段不恢复已取消日程，需要重新安排。

固定时段按半开区间判断重叠，相邻日程可连续安排；已完成和已取消日程不参与冲突。截止时间不占固定时段。日程时间使用服务器完成时刻，防止客户端伪造完成时间。

## 文件处理

先由云函数为当前用户和目标记录生成随机性来源于请求 ID 的唯一上传路径；客户端按私有权限上传；云函数校验环境、预约归属路径、文件签名与体积，再写入业务引用。不能直接提交他人的 fileID 作为简历。

文件下载继续走当前微信身份的私有存储 API。没有公开下载链接，也不在数据库保存临时公开 URL。删除采用待删队列：先提交删除业务引用，再删除云文件，失败保留队列供后续写入或用户触发清理。重复删除文件不会恢复业务引用。

上传失败的恢复信息只包含文件 ID、预约 ID、请求版本，按环境和 owner 隔离在本机。业务正文不落本地缓存，读取失败不会换成样例或离线数据。导出过程临时写入本地 JSON，并在微信文件分享操作结束后清理该临时文件。

## 规模与兼容性

本版本面向个人求职工作区，文档采用 700 KiB 的应用层上限，为数据库字段及响应保留余量；超限拒绝整次更新，没有静默丢失或切片读取。每次读取完整工作区，适合个人数据量，暂不具备大量多年档案的分页存储能力。

要扩展为高数据量服务，应另建 jobs / agenda / notes / assets / events 集合，通过服务器端事务、独立幂等收据和分页查询迁移，并对现有 `schemaVersion: 1` 工作区做备份与可重试迁移。不要在运行中单纯删除容量校验；当前所有展示和并发模型都建立在单文档基础上。

文件上传预约保存 24 小时，最多 10 个未完成预约；过期预约在下一次预约时移除。已上传但没有完成登记、且本地恢复记录又丢失的文件可能成为孤立对象，需要管理员对照清理。没有自动定时清理或备份作业，部署指南列出维护方式。

本项目不会修改网站的 package.json、src、数据库迁移、环境变量、构建或运行脚本。外层 Git 仓库已有 CI 可能由常规推送自然触发，但本任务没有执行或声称通过任何测试和验收。
